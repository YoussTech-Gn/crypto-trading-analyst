## Defects reproduced by Codex

**1. A final kill at 100 can become a pass at 200.** With the ADR-043 fixture, the upper 95% bound at 100 was -1.000R. At 200 the same function printed a pass with a lower bound of +0.722R. ADR-036 allows the second look only if the first was undecided. There is a second route to a moving verdict: review sorts by signal-open time and selects the currently closed rows. A late settlement of an older signal can change membership of an earlier checkpoint. The existing unit test covers separate checkpoints but never tries to overturn a terminal one. [Verdict and review](packages/journal/forward.py) · [Existing checkpoint test](tests/unit/test_forward_journal.py)

**2. A successful scan write can erase an owner decision.** In a disposable journal, a decision and a scan both loaded row A. The decision saved `skipped`. The scan added B and saved its older copy. The final file contained A and B but A's choice was empty. A valid atomic file replacement protects the file's structure while still allowing this loss. The chain head for signal fields does not capture an in-window owner choice. `settle` and commands that automatically mark absences also write this file. [Load, save and command paths](scripts/forward_journal.py) · [Hash fields and owner seals](packages/journal/forward.py)

**3. Future missing data changes today's cross-sectional inputs.** Deleting one peer candle at time 310 changed BTC's two percentile ranks at time 300 from 0.5 to 1.0 and its active count from two to one. The dataset first asks whether each peer has a complete future label horizon and then ranks the survivors. Training weights also use that count. The sampled bias check tests a single symbol's features, before cross-sectional assembly. Build the point-in-time peer universe and ranks before joining eligible labels. Acceptance requires identical current features and counts after any change confined to a peer's future. The historical magnitude is unknown. FG1 keeps its published rejection. [Dataset assembly](packages/learning/dataset.py) · [Bias checker](packages/backtest/bias.py) · [Reproduction details](reports/failure_meeting_audit.txt)

**Claude Code, live response, summarized by Codex.** Fix the write race first. A checkpoint cannot be durable while a stale writer can replace it. Serialize the read, modification and commit, or use an atomic version check with retry. Persist the ordered signal IDs used at each look. It also proposed a lock-contention test, checks at 99, 100, 101, 199 and 200, and a review of a 200-row file containing an incorrect verdict. Gemini answered the same owner-approved abstract as Claude. Neither peer inspected the repository in this round.

**Codex, response and points of disagreement.** I accept the shared repair order. Fetch market data outside the critical section, then reload current records and merge by ID during a short protected commit. Include the scan watermark in the consistency test. I would amend Claude's proposed final state because ADR-036 kills an undecided recipe at 200. I would narrow Gemini's recomputation test to checking the frozen cohort and reporting any mismatch. Replacing an earlier terminal verdict using all 200 rows would reproduce defect 1. The implementation also needs a documented cohort order for simultaneous closes, delayed settlement and first review after a threshold has already been crossed.

The other findings above are Codex's audit items and remain open for peer challenge. The expected deliverable is a reproducible paper verdict for each recipe once it reaches the applicable checkpoint.

## Repair sequence and definition of done

1. **Protect observation capture.** Exercise the normal scan, decide and settle commands against disposable state. Force two commands to overlap using a barrier. After retry, both the new signal and owner decision must survive. Interrupt between journal and watermark writes and restart. Each signal must appear once and the watermark must never skip an uncommitted signal.
2. **Freeze the first eligible verdict.** Specify the cohort order before any live verdict. Store checkpoint membership and the terminal outcome durably. At 99 show collecting. At 100 a conclusive result survives all later records, backfill, restart and review. Only an undecided first look reaches 200, where an interval containing zero is killed. Test both reversal directions and a first review delayed until after 200.
3. **Verify coverage and resume interpretation.** Demonstrate partial-feed recovery and view/journal agreement on the same close. Then continue measuring the three original paper recipes under ADR-036. If no recipe meets its frozen rule, rejection is a valid planned result. A prospective learning study needs causal peer ranks and thresholds before another run.
